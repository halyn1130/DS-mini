# ESS 배터리 수명 예측

초기 5사이클의 측정 정보로 단수명 배터리를 초기에 구분하는 **Binary Classification** 프로젝트이다.
배터리의 수명 분포와 열화 특성을 분석하고, Logistic Regression과 Random Forest를 비교하여 향후 ESS용 배터리 선별 및 추가 검사 우선순위 설정에 활용할 가능성을 탐색한다.


## 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 데이터셋 | MIT-Stanford Battery Dataset (Severson et al., Nature Energy 2019)의 Kaggle 배포본 |
| 분석 데이터 | Batch 1 (2017-05-12), Batch 2 (2018-02-20), Batch 3 (2018-04-12) |
| 태스크 | Classification: 초기 5사이클 기반 장·단수명 분류 |
| 타깃 | 단수명: Cycle Life <500 → 1 / 장수명: Cycle Life >1,000 → 0 |
| 제외 대상 | 500~1,000사이클의 중간 수명 기록, 수명 결측 기록 |
| 학습·평가 방식 | 세 배치의 대상 기록을 합친 층화 중첩 교차검증: 외부 5-fold 평가, 내부 3-fold 튜닝 |
| 현재 상태 | 원본 기록과 원본 수명 라벨 기준 탐색 실험 완료. 물리 셀 식별·라벨 정제 후 최종 검증 필요 |

원본 기록은 139개이며, 수명 라벨이 있는 기록은 129개다. 이 중 단수명 28개와 장수명 36개, 총 **64개 기록**을 현재 분류 실험에 사용했다. 중간 수명 65개와 라벨 결측 10개는 제외했다. 500과 1,000사이클은 중간 수명에 포함한다.

## EDA
### Cycle Life 분포
| 배치 | 유효 수명 라벨 | 수명 중앙값 | 단수명 <500 | 장수명 >1,000 |
| --- | ---: | ---: | ---: | ---: |
| Batch 1 | 46 | 858.5 | 0 (0.00%) | 10 (21.74%) |
| Batch 2 | 39 | 472.0 | 28 (71.79%) | 3 (7.69%) |
| Batch 3 | 44 | 1,005.5 | 0 (0.00%) | 23 (52.27%) |
| 전체 | 129 | — | 28 (21.71%) | 36 (27.91%) |

비율의 분모는 배치별 유효 수명 라벨 수다. Batch 1은 수명 편차가 가장 작고, Batch 2는 짧은 수명 구간에 집중되며 일부 긴 기록이 평균을 높인다. Batch 3는 대표 수명과 편차가 모두 크다.

**핵심 발견:** 단수명 28개가 모두 Batch 2에 있어 수명 특성과 배치 차이가 섞일 가능성이 크다. 배치별 IQR 기준에서 짧은 쪽 이상치는 없었지만, 이것이 문제 셀이 없다는 뜻은 아니다.


### 열화 곡선 분석

초기 방전 용량은 유사한 수준이지만, 100~300사이클 구간에서 Batch 2의 용량 감소가 상대적으로 컸다. 두 구간 선형 근사로 찾은 knee 후보 위치의 중앙값은 Batch 1 약 630, Batch 2 약 353, Batch 3 약 808사이클이었다.

knee는 평활화 후 전·후 구간 모두 감소하고 후반 감소 속도가 2배 이상이며, 단일 직선 대비 SSE가 30% 이상 줄어드는 경우의 탐색적 후보다. 확정된 열화 시작점으로 해석하지 않는다.

**핵심 발견:** 초기 용량의 크기만으로 수명을 판단하기 어렵고, 용량 유지 특성이 중요하다. 전체 곡선으로 찾은 knee와 100→300사이클 감소율은 초기 5사이클 모델에서 사용할 수 없다.

### ΔQ(V) 곡선 분석

같은 전압에서 `ΔQ(V) = Q100(V) − Q10(V)`를 계산했다. Batch 2의 단수명 그룹은 장수명 그룹보다 큰 음의 변화를 보였고, 배치별 중앙값으로 구분한 상대 장·단수명 비교에서도 단수명 그룹의 변화가 더 컸다. 두 그룹 기준은 별도 분석이다.

`log10(var(ΔQ))`와 수명의 Pearson 상관계수는 전체 기준 **−0.851**이었으며, 각 배치에서도 음의 관계가 나타났다.

**핵심 발견:** 초기 방전 곡선 변화는 수명 예측의 유용한 후보 지표다. 다만 100사이클 정보가 필요하므로 이번 5사이클 모델 입력에서는 제외했다.

### 충전 속도(C-rate)와 수명의 관계

Batch 1의 일부 정책에서 4C·4.8C·5.4C 평균 수명은 각각 1,226.5·753.0·546.5사이클이었다. 각 정책의 표본은 2개로 작다. 실제 충전 전류와 수명의 상관 방향도 배치·정책 그룹별로 일관되지 않았다.

**핵심 발견:** 일부 비교에서는 높은 충전율과 짧은 수명이 함께 나타나지만, 충전율만으로 수명을 설명할 수 없다. 정책 조합, 온도, 배치 및 표본 수를 함께 고려해야 한다.

### 초기 지표와 다중공선성

초기 1~100사이클 평균 지표를 분석했을 때 충전시간은 배치별로 수명과 양의 상관을 보였지만, 통합 분석에서는 음의 상관을 보였다. 평균 온도와 최고 온도의 상관계수는 전체 기준 0.875였고 VIF는 각각 8.17, 6.34였다.

**핵심 발견:** 배치 효과와 온도 피처의 중복 정보를 고려해야 한다. 100사이클 EDA에서 관찰한 관계가 초기 5사이클에서도 유지된다고 가정하지 않는다.



## Modeling

### 피처 엔지니어링 전략

첫 사이클의 초기화·0값 영향을 피하고 초기 5사이클 내 정보만 사용하기 위해 **실제 cycle 번호 2~5**를 선택하였다.

| feature | 계산 | 선정 근거 |
| --- | --- | --- |
| 방전 용량 평균 | cycle 2~5의 QDischarge 평균 | 초기 용량 수준 |
| 방전 용량 변화량 | Q5 − Q2 | 초기 용량 변화. 초기 활성화 영향도 가능하므로 열화량으로 단정하지 않음 |
| 내부저항 평균 | cycle 2~5의 IR 평균 | 초기 저항 특성 |
| 평균 온도 평균 | cycle 2~5의 Tavg 평균 | 초기 열적 상태 |
| 최고 온도 평균 | cycle 2~5의 Tmax 평균 | 초기 고온 특성 |
| 충전시간 평균 | cycle 2~5의 chargetime 평균 | 충전 동작 특성 |

cycle 2~5가 없거나 중복된 기록은 제외한다. 개별 피처의 비유한 값과 용량·저항·충전시간의 비양수 값은 결측 처리하며, 모든 피처가 결측이면 제외한다. 결측 대체는 각 학습 fold의 중앙값으로 수행한다.

수명, 배치 ID, 기록 ID는 모델 입력에 넣지 않는다. ΔQ100−10, 전체 기록 knee, 100→300사이클 감소율도 예측 시점 이후의 정보이므로 제외한다. 온도 두 피처는 현재 모두 유지하며, 선형 모델에는 L2 규제를 적용한다. 온도 피처 제거의 효과는 아직 별도로 검증하지 않았다.

### 모델 선택 및 근거

| 역할 | 모델 | 선택 근거 |
| --- | --- | --- |
| 기준선 | DummyClassifier: 다수 클래스 / 모두 단수명 | 단순 예측 대비 개선 여부와 Recall만 높이는 예측을 구별 |
| 우선 후보 | Logistic Regression (L2 규제) | 적은 표본에서 단순한 구조로 시작하고 표준화 계수로 예측 방향 해석 |
| 비교 후보 | Random Forest (깊이 제한) | 비선형 관계와 피처 조합이 분류에 도움이 되는지 비교 |

**최종 모델은 아직 확정하지 않았다.** 현재 결과에서는 Logistic Regression을 우선 검토한다. 단수명 Recall·F1이 더 높고 fold별 Accuracy 변동도 더 작았지만, 물리 셀·라벨 정제와 배치 편향 점검 후 다시 판단해야 한다.

Logistic Regression은 이름에 Regression이 들어가지만 여기서는 단수명 클래스일 확률을 출력하는 분류 모델이다. 실제 수명으로 정답 라벨을 먼저 만들며, 회귀로 수명을 예측한 뒤 기준을 적용하는 방식이 아니다.

### Pipeline 및 검증 전략

- Logistic Regression: 중앙값 결측 대체 → 표준화 → L2 규제 분류. `C`는 0.01/0.1/1, 클래스 가중치는 없음/balanced를 비교한다.
- Random Forest: 중앙값 결측 대체 → 100개 트리. 최대 깊이 2/4, 리프 최소 표본 2/5, 클래스 가중치 없음/balanced를 비교한다.
- 외부 층화 5-fold는 성능 평가에, 내부 층화 3-fold는 파라미터 선택에 사용한다. 모델과 기준선은 같은 외부 분할을 사용하며 난수 시드는 42다.
- 전처리는 Pipeline 안에서 각 학습 fold에만 적합한다. 튜닝 지표는 단수명 Recall에 더 큰 가중치를 주는 F2다.
- 분류는 모델의 기본 결정 규칙을 사용하고 임계값 튜닝은 하지 않았다.

**분할의 한계:** 현재는 원본 기록 ID의 중복만 차단했다. 원 저자 정제 예시와 현재 Batch 2 파일의 버전·기록 수가 달라 연결 인덱스와 수명 보정을 그대로 적용하지 않았다. 서로 다른 기록이 동일 물리 셀인지 확인한 뒤 셀별 한 행 또는 그룹 분할로 재평가해야 한다.

## 성능 결과

원본 64개 기록의 외부 교차검증 예측(OOF)을 합친 **탐색 결과**다. 별도의 독립 Batch 2 테스트 성능이나 배포 성능이 아니다. Precision·Recall·F1·F2의 양성 클래스는 단수명(1)이다.

| 모델 | Accuracy | Precision | Recall | F1 | F2 | Balanced Accuracy |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 다수 클래스 기준선 | 56.25% | 0.000 | 0.000 | 0.000 | 0.000 | 0.500 |
| 모두 단수명 기준선 | 43.75% | 0.438 | 1.000 | 0.609 | 0.795 | 0.500 |
| Logistic Regression | **93.75%** | **0.929** | 0.929 | **0.929** | **0.929** | **0.937** |
| Random Forest | 92.19% | 0.926 | 0.893 | 0.909 | 0.899 | 0.919 |

| 모델 | 장수명 정답(TN) | 장수명 오탐(FP) | 단수명 누락(FN) | 단수명 정답(TP) |
| --- | ---: | ---: | ---: | ---: |
| Logistic Regression | 34 | 2 | 2 | 26 |
| Random Forest | 34 | 2 | 3 | 25 |

Logistic Regression은 64개 중 60개, Random Forest는 59개를 맞혔다. 두 모델의 차이는 단수명 한 개의 탐지 여부다. 모두 단수명 기준선은 Recall이 1이지만 장수명 36개를 모두 오분류하므로 Recall만으로 모델을 선택하지 않는다.

fold별 Accuracy 평균 ± 표준편차는 Logistic Regression **93.72% ± 3.52%p**, Random Forest **92.31% ± 9.42%p**다. 이는 위의 통합 OOF Accuracy와 계산 방식이 다르며, 표준편차는 신뢰구간이 아니다. 학습 F2와 외부 검증 F2 차이의 fold 평균은 각각 0.043, 0.080이었다.

목표 Recall과 허용 가능한 오탐 수준은 아직 정하지 않았으므로 목표 달성 여부는 판정하지 않는다. 상세 결과는 `day2_experiments/results/overall_metrics.csv`와 `fold_metrics.csv`에서 확인할 수 있다.

### Accuracy 말고 다른 성능지표도 확인한 이유

처음에는 전체 중 얼마나 맞혔는지 보면 되니까 Accuracy로 비교하면 되겠다고 생각할 수 있음. 그런데 이번 목적은 **초기 5사이클만 보고 단수명 배터리를 미리 찾아내는 것**임. 전체 정답률이 높더라도 정작 단수명 배터리를 놓치고 있다면 목적에 맞게 잘 예측했다고 보기 어려움. 그래서 얼마나 맞혔는지와 함께 **무엇을 놓쳤고, 어떤 방향으로 틀렸는지**도 확인했음.

현재 전체 표본은 장수명 36개, 단수명 28개로 극심한 불균형은 아님. 다만 배치별로 보면 구성이 많이 다름. Batch 2는 31개 중 28개가 단수명이고, Batch 1·3은 분류 대상에 장수명만 남아 있음. 따라서 단순히 “데이터가 불균형해서 지표를 추가했다”기보다는, **단수명 탐지라는 목적과 배치별 클래스 구성을 함께 고려한 것**임.

#### 1. Accuracy — 전체적으로 얼마나 맞혔는가?

`Accuracy = (TP + TN) / 전체 기록 수`

가장 직관적으로 전체 분류 성능을 확인할 수 있는 지표임. Logistic Regression은 64개 중 60개를 맞혀 93.75%, Random Forest는 59개를 맞혀 92.19%였음.

그런데 이 숫자만 보면 틀린 기록이 단수명인지 장수명인지 알 수 없음. 예를 들어 같은 4개를 틀려도 단수명을 4개 놓친 경우와 장수명을 4개 잘못 의심한 경우는 이후 판단이 달라질 수 있음. 그래서 Accuracy는 전체 성능을 보는 지표로 사용하고, 단수명 탐지 성능은 따로 확인했음.

#### 2. Recall — 실제 단수명 배터리를 얼마나 찾아냈는가?

`단수명 Recall = TP / (TP + FN)`

이번 목적과 가장 직접적으로 연결되는 지표라고 판단했음. 실제 단수명 배터리 중 모델이 단수명으로 찾아낸 비율이므로, **추가 확인이 필요한 배터리를 얼마나 놓치지 않았는지** 볼 수 있음.

Logistic Regression은 단수명 28개 중 26개를 찾아 Recall 92.86%, Random Forest는 25개를 찾아 89.29%였음. 즉 두 모델의 전체 Accuracy 차이는 작지만, 단수명을 놓친 개수는 각각 2개와 3개라는 차이가 있었음.

다만 Recall만 높다고 좋은 모델이라고 할 수는 없음. 모든 배터리를 단수명이라고 하면 실제 단수명은 전부 포함되므로 Recall이 100%가 됨. 대신 장수명까지 모두 추가 검사 대상으로 판단하게 됨. 이 문제를 같이 보기 위해 Precision도 확인했음.

#### 3. Precision — 단수명이라고 판단한 배터리 중 실제 단수명은 얼마나 되는가?

`단수명 Precision = TP / (TP + FP)`

단수명으로 분류한 결과를 얼마나 믿을 수 있는지 확인하기 위한 지표임. ESS 적용을 생각하면 단수명으로 분류된 셀에 추가 검사를 진행할 수 있는데, 오탐이 많으면 실제로는 장수명인 셀에도 검사 시간과 비용이 들어갈 수 있음.

Logistic Regression은 단수명이라고 예측한 28개 중 26개가 실제 단수명이라 Precision 92.86%였음. Random Forest는 27개 중 25개로 92.59%였음. 반면 모두 단수명으로 예측하는 기준선은 64개 중 실제 단수명이 28개뿐이므로 Precision이 43.75%임.

따라서 Recall로 놓친 단수명을 확인하고, Precision으로 단수명이라고 너무 많이 판단하고 있는지도 같이 봤음. 단수명을 많이 잡는 것과 불필요한 검사를 줄이는 것 사이의 균형이 필요하다고 생각했음.

#### 4. F1 — Precision과 Recall을 같이 보면 어떤가?

`F1 = 2 × Precision × Recall / (Precision + Recall)`

Precision과 Recall의 조화평균으로, 둘 중 하나만 높을 때 점수가 높게 나오지 않도록 함께 확인하는 지표임. Recall은 높은데 오탐이 너무 많거나, Precision은 높은데 단수명을 많이 놓치는 모델을 구별하는 데 도움이 됨.

모두 단수명 기준선은 Recall이 1.000이어도 F1은 0.609였음. Logistic Regression은 0.929, Random Forest는 0.909로, 단순히 전부 단수명으로 판단하는 것보다 두 지표를 함께 고려했을 때 나은 결과를 보였음.

다만 단수명 기준 F1에는 장수명을 맞힌 TN이 직접 들어가지 않으므로, 이것만으로 두 클래스 전체를 설명하지는 않았음.

#### 5. F2 — 단수명을 놓치지 않는 쪽에 비중을 더 주면 어떤가?

`F2 = 5 × Precision × Recall / (4 × Precision + Recall)`

F1보다 Recall에 더 큰 비중을 두는 지표임. 이번에는 단수명 위험 배터리를 조기에 찾아내는 것이 목적이므로, **모델 파라미터를 고르는 내부 교차검증에서는 F2를 사용했음.** Recall만 보고 고르면 전부 단수명이라고 하는 예측도 유리해질 수 있어서 Precision도 함께 반영하는 지표를 선택했음.

단, F2를 쓴다고 무조건 오탐이 적어지는 것은 아님. 실제로 모두 단수명 기준선도 F2가 0.795로 나왔으므로, 최종 결과에서는 Precision과 FP 개수를 계속 같이 확인해야 함. 또한 F2는 이번 목적에 맞춰 정한 평가 기준이지, 실제 현장에서 단수명 누락 비용이 오탐 비용보다 몇 배 크다고 검증한 결과는 아님.

#### 6. Balanced Accuracy — 장수명과 단수명을 같은 비중으로 보면 어떤가?

`Balanced Accuracy = (단수명 Recall + 장수명 Recall) / 2`

일반 Accuracy는 표본이 많은 클래스의 영향을 더 크게 받음. Balanced Accuracy는 각 클래스의 Recall을 먼저 구한 뒤 평균을 내므로, 장수명과 단수명을 같은 비중으로 볼 수 있음.

현재 전체 데이터에서 모두 장수명으로 예측하면 Accuracy는 56.25%지만, 단수명은 하나도 찾지 못하므로 Balanced Accuracy는 0.5임. 모두 단수명으로 예측해도 장수명을 하나도 맞히지 못하므로 0.5임. 두 기준선의 Accuracy는 다르지만, 한쪽 클래스만 맞힌다는 점을 이 지표로 확인할 수 있음.

Logistic Regression의 Balanced Accuracy는 0.937, Random Forest는 0.919였음. 다만 이 지표가 배치 편향까지 해결해 주는 것은 아님. 두 클래스에 대한 예측이 균형적인지 보는 지표이지, 새로운 배치에도 잘 맞는다는 증거는 아님.

#### 7. 혼동행렬과 Batch별 결과 — 실제로 어떤 기록을 틀렸는가?

비율만 보면 오류 규모가 잘 와닿지 않아서 TP·TN·FP·FN의 실제 개수도 확인했음. 이번 기준은 단수명=1, 장수명=0이므로 아래처럼 읽으면 됨.

| 구분 | 실제 → 예측 | 이번 프로젝트에서의 의미 |
| --- | --- | --- |
| TP | 단수명 → 단수명 | 찾아낸 단수명 기록 |
| FN | 단수명 → 장수명 | 놓친 단수명 기록 |
| FP | 장수명 → 단수명 | 불필요한 추가 검사로 이어질 수 있는 오탐 |
| TN | 장수명 → 장수명 | 올바르게 구분한 장수명 기록 |

여기에 Batch별 결과도 나눠 봤음. Batch 2에서는 모두 단수명으로 예측해도 Accuracy가 90.32%로 높게 나옴. Logistic Regression도 같은 Accuracy이지만, 기준선은 장수명 3개를 전부 놓치는 반면 모델은 장수명 2개를 맞히고 단수명 2개를 놓쳤음. **같은 Accuracy여도 실제 오류의 내용은 다르다는 것**을 확인할 수 있음.

Batch 3의 Accuracy 100%도 장수명 23개를 모두 맞혔다는 의미임. 단수명이 없어서 해당 배치의 단수명 Recall은 계산할 수 없으며, 0%나 100%로 대신 표현하지 않았음.

#### 8. fold별 변동과 학습·검증 차이 — 나누는 방식에 따라 결과가 많이 달라지는가?

표본이 64개뿐이라 기록 한두 개의 예측 차이도 점수에 영향을 줄 수 있음. 그래서 통합 점수뿐 아니라 fold별 평균·표준편차와 학습·검증 F2 차이도 확인했음. 학습에서는 잘 맞는데 검증에서 점수가 떨어지거나 특정 fold에서만 성능이 낮다면, 전체 점수만 보고 안정적인 모델이라고 판단하기 어렵기 때문임.

현재는 Logistic Regression의 fold별 Accuracy 변동이 Random Forest보다 작았음. 다만 5개 fold의 표준편차는 불확실성 전체를 나타내는 신뢰구간이 아니며, 이 결과만으로 모델의 우위를 확정하지는 않았음.

이번에는 **Accuracy로 전체 정답률, Recall로 단수명 누락, Precision으로 오탐, F1·F2로 두 지표의 균형, Balanced Accuracy로 클래스별 성능을 확인했음.** 모델 튜닝은 내부 검증의 F2로 수행했고, 외부 검증 결과는 여러 지표와 오류 개수를 함께 보고 해석했음. 목표 Recall과 허용 오탐 수준은 아직 정하지 않았으므로, 현재 점수만으로 실제 운영에 충분하다고 판단하지는 않았음.

### Batch별 Test 성능

학습·평가 분할은 그대로 유지하고, 각 기록이 외부 fold의 Test에 포함되었을 때 얻은 OOF 예측을 Batch별로 모았다. 아래 기록 수는 5개 외부 fold에 걸쳐 평가한 고유 기록 수이며, 한 번의 분할에서 사용한 Test 크기가 아니다.

| 모델 | 평가 배치 | 기록 수 (장수명 / 단수명) | 맞힌 기록 수 | Accuracy | 단수명 Recall |
| --- | --- | ---: | ---: | ---: | ---: |
| Logistic Regression | Batch 1 | 10 (10 / 0) | 9 | 90.00% | 계산 불가 |
| Logistic Regression | Batch 2 | 31 (3 / 28) | 28 | 90.32% | 92.86% |
| Logistic Regression | Batch 3 | 23 (23 / 0) | 23 | 100.00% | 계산 불가 |
| Random Forest | Batch 1 | 10 (10 / 0) | 9 | 90.00% | 계산 불가 |
| Random Forest | Batch 2 | 31 (3 / 28) | 27 | 87.10% | 89.29% |
| Random Forest | Batch 3 | 23 (23 / 0) | 23 | 100.00% | 계산 불가 |

Batch 1·3에는 장수명만 있으므로 단수명 Recall을 계산할 수 없다. Batch 3의 Accuracy 100%는 장수명 23개를 모두 맞혔다는 뜻이며, 해당 배치의 단수명 탐지 능력을 입증하지 않는다. 항상 장수명으로 예측하는 기준선도 이 두 배치에서는 Accuracy 100%를 얻는다.

Batch 2에서는 Logistic Regression이 단수명 28개 중 26개, Random Forest가 25개를 찾았다. 두 모델 모두 장수명 3개 중 2개를 맞혔다. Batch 2의 모두 단수명 기준선도 Accuracy 90.32%이므로, Accuracy와 함께 클래스별 오류를 확인해야 한다.

각 외부 fold의 학습 데이터에도 동일 배치의 다른 기록이 포함된다. 따라서 이 표는 **배치별 Test 예측 분석**이며, 특정 배치를 학습에서 완전히 제외한 새로운 배치 평가가 아니다. 상세 수치는 `day2_experiments/results/batch_metrics.csv`에 저장되어 있다.

분류에서는 수명 예측 오차의 크기 대신 **FN·FP와 잘못된 예측의 확률**을 확인했다. 아래 ID의 셀 번호는 0부터 시작하는 원본 기록 번호이며, 물리 셀 식별자가 아니다.

| 기록 | 실제 수명 | 공통 오류 | Logistic Regression의 단수명 확률 | Random Forest의 단수명 확률 |
| --- | ---: | --- | ---: | ---: |
| b1c9 | 1,054 | 장수명을 단수명으로 분류(FP) | 0.506 | 0.574 |

원인 가설은 초기 5사이클 정보의 부족, 배치·정책 차이, 적은 표본에 따른 분할 변동이다. 초기 피처의 공통 이상 패턴이나 인과적 원인은 아직 확인하지 않았다. 다음 단계에서는 오류 기록의 측정값·결측·정책·라벨을 확인하고, 정제 후에도 같은 오류가 반복되는지 점검한다. 임계값 변경은 외부 평가 결과에 맞추지 않고 별도의 학습·검증 과정에서 결정한다.

## ESS 도메인 해석

### 활용 가능한 의사결정

추가 검증을 전제로, 입고·초기 시험 단계에서 단수명 가능성이 높은 셀을 **추가 용량 시험이나 검사 대상으로 우선 선정하는 보조 지표**로 활용할 수 있다. 단수명 누락(FN)은 추가 검사가 필요한 셀을 놓치는 문제, 장수명 오탐(FP)은 불필요한 검사 비용을 늘리는 문제로 해석할 수 있다.

현재 모델은 수명 구간을 분류하므로 실제 교체 시점이나 잔여수명을 직접 제공하지 않는다. 셀 단위 실험 결과만으로 BESS의 운전 제어·교체·안전 판단을 자동화하는 근거는 확보되지 않았다.

### 한계와 실 배포를 위한 추가 검증

- **데이터 정제:** 물리 셀 식별, 연속 기록 연결, 수명 라벨과 제외 기준을 확인해 학습·평가 간 중복을 방지해야 한다.
- **배치 편향:** 단수명이 Batch 2에만 있다. 다른 배치에서도 장·단수명 표본을 확보하여 새로운 배치에 대한 성능을 평가해야 한다.
- **적용 범위:** 중간 수명을 제외한 두 그룹의 구분 결과다. 모든 배터리를 대상으로 한 선별 성능이나 전체 모집단의 보정된 위험 확률로 해석할 수 없다.
- **현장 검증:** 실제 ESS의 셀 종류, 온도, 충·방전 조건, 운용 기간 및 팩 구성에서 성능이 유지되는지 별도 데이터로 검증해야 한다.
- **운영 기준:** 누락 비용과 추가 검사 비용을 바탕으로 목표 Recall과 허용 오탐을 정하고, 확률 보정·판정 임계값·현장 성능 모니터링을 검토해야 한다.
